# Лабораторные по 3D-моделированию: методички под 3ds Max → выполнение в Blender

## Кто пользователь и что ему нужно

- Студент, курс «Мультимедиа технологии». Методички написаны под 3ds Max, но 3ds Max ему недоступен, поэтому всё делается в **Blender 5.2.1 с русским интерфейсом** на Windows.
- Для сдачи ему нужны:
  1. **Отчёт** — понятный текст по шагам и рисунки с подписями «Рис. N — …». Оформление (титульник, шрифты, поля) он делает сам.
  2. **Файл .blend**, который он откроет на защите и покажет, где какая настройка («потыкать»).
  3. **Понимание** — для этого пишется шпаргалка к защите.
- Его просьба: **если что-то не переносится из 3ds Max или пришлось сделать иначе — обязательно помечать.**
- Отвечать и писать всё по-русски, просто и коротко.

## Что уже сделано и как делать новую лабу

Готово (всё в `output/`, ветка `claude/dazzling-edison-gcfby3`, в `main` не сливалось):
- лабы 3–4 — образцы в `examples/`;
- лабы 5, 6, 7, 8 — `output/lab5/` … `output/lab8/`; сводка и список отклонений — `output/ИТОГ.md`;
- скрипты, которыми всё собрано, — `scripts/labN/` (`build_labN.py` → `render_labN.py` → `make_reportN.js`), общие функции отчёта — `scripts/report_common.js`, PNG → JPG — `scripts/tojpg.py`.

Новую лабу делай по тому же конвейеру (лучший образец — `scripts/lab7/`, там несколько сцен):
1. Методичку (PDF/DOCX от пользователя) положи в `metodichki/N.*`, прочитай целиком, составь таблицу «3ds Max → Blender». Если файл пришёл без пояснений или задание неоднозначно — спроси (AskUserQuestion), прежде чем делать.
2. `scripts/labN/build_labN.py` → `output/labN/ЛабаN_Blender.blend`. Геометрию строй через bmesh (операторы bpy.ops в фоне без окна работают не всегда, а объекты в чужие сцены не добавляют).
3. `render_labN.py` → `build/figsN/*.png` (Cycles CPU, 40 сэмплов, денойз), контакт-лист, просмотр, правки, повтор.
4. `python scripts/tojpg.py build/figsN build/figsN_jpg` → `make_reportN.js` → `tools/fixdocx.py` → PDF через soffice → просмотр страниц.
5. Шпаргалка `output/labN/Шпаргалка_защита_ЛабаN.md`, раздел в `output/ИТОГ.md` (сделано / отличия от методички / скрины по рамкам).
6. Проверка .blend повторным открытием, commit, push в рабочую ветку.

`build/` и `.venv/` в .gitignore — после перезапуска контейнера их нужно пересоздать (venv — см. «Окружение»; `npm install docx` — в любую папку, запуск с `NODE_PATH=<эта папка>/node_modules`).

## Окружение

- Blender как Python-модуль: `pip install bpy==5.0.1` — **нужен Python 3.11** (колёса только cp311). Если его нет:
  `pip install uv && uv python install 3.11 && uv venv -p 3.11 .venv && uv pip install -p .venv bpy==5.0.1 pillow numpy polib python-docx`
- Файлы, сохранённые из bpy 5.0.1, открываются в Blender 5.2.1 у пользователя.
- Рендерить можно только **Cycles на CPU** (EEVEE без GPU не работает). При этом в самом .blend оставляй движок **EEVEE**: у пользователя он быстрый.
- Отчёт: npm-пакет `docx` (v9, `npm install docx`). Генератор пиши по образцу `examples/lab4/make_report4.js`. **После генерации обязательно** `python tools/fixdocx.py Отчет.docx`: docx-js пишет границы абзаца (`w:pBdr`) в неверном порядке, Word на это ругается.
- Проверка отчёта: если есть LibreOffice — `soffice --headless --convert-to pdf`, затем `pdftoppm` и просмотр страниц картинками. Если нет — хотя бы открыть файл через python-docx.
- В скриптах из `examples/` зашиты пути старого окружения (`/tmp/claude-0/...`) — замени на пути этого репозитория.
- `tools/lab4_common.py` — полезные функции: материалы, кривые, камера, свет, мир (hex-цвета переводятся в линейные).

## Русские названия интерфейса

- `tools/ru.po` — официальный русский перевод Blender (5.3 alpha, совпадает с 5.2). **Все названия пунктов меню и параметров в отчёте и шпаргалке бери оттуда** (через `polib`), а не придумывай.
  Примеры: Color Ramp = «Градиентная карта», Bump = «Карта неровностей», Extrude у кривой = «Экструдировать», Selectable = «Доступно для выделения», Copy as New Driver = «Копировать как новый драйвер», Scripted Expression = «Скриптовое выражение».
- Учитывай `msgctxt`: у одного слова бывают разные переводы в разных местах.
- Если перевода нет — пиши английское название: так и будет в интерфейсе (например, у дополнений: Round Cube, Curve Profiles).

## Правила качества (выработаны на лабах 3–4)

1. Сначала прочитай методичку целиком (PDF по страницам) и составь таблицу «3ds Max → Blender».
2. **Любое поведение Blender, в котором есть сомнения, проверяй скриптом в bpy**, а не по памяти. Например, в лабе 3 так выяснилось, что ось изгиба «Простой деформации» — это ось, *вокруг* которой гнётся объект.
3. **Масштаб.** Числа из методичек (радиусы 40–70) в Blender становятся метрами. Последствия:
   - стандартные камера и лампа оказываются внутри объекта → ставь свою камеру и свет;
   - у камеры `clip_end` по умолчанию 100 → ставь 1000 и больше;
   - у узла «Карта неровностей» «Расстояние» по умолчанию 0.001 → ставь около 1, иначе рельефа не видно.
4. **В .blend:**
   - модификаторы НЕ применять — пользователь показывает их настройки на защите;
   - понятные русские имена объектов, модификаторов и материалов;
   - коллекции по заданиям; если заданию нужен свой свет и фон — отдельная сцена (как в лабе 4) с названием «1 — …», «2 — …»;
   - скрытая коллекция «Этапы … (скрыто)» (`hide_viewport` у layer collection + `hide_render`) с копиями модели на промежуточных шагах — по ним пользователь снимает скриншоты этапов;
   - камера и свет настроены так, что F12 сразу даёт хороший кадр;
   - картинки упаковывать внутрь файла (`image.pack()`).
5. **Драйверы — только «простые выражения»** (`driver.is_simple_expression == True`), иначе у пользователя без Auto Run Python они не сработают.
6. **Рисунки для отчёта:**
   - рендер Cycles, 40 сэмплов, денойз;
   - этапы — серый материал, чёрный каркас (копия объекта с модификатором Wireframe) и «студийный» свет со стороны камеры (см. `examples/lab4/render_lab4.py`);
   - для видов сверху и спереди — ортографическая камера;
   - **все рендеры просмотри** (собери контакт-лист) и поправь кадрирование и свет, прежде чем собирать отчёт.
7. **Скриншоты интерфейса сделать нельзя.** Вместо них в отчёте — жёлтая рамка «ВСТАВИТЬ СКРИНШОТ. …» с точной инструкцией: какую сцену и объект выбрать, какую вкладку открыть, что снять. Если для скрина нужно выполнить действие — допиши «потом Ctrl+Z».
8. Не утверждать в отчёте того, чего не было. Например, если текстура собрана скриптом, не писать «выполнено в Photoshop».

## Формат отчёта (образец — `examples/lab4/Отчет_Лаба4.docx`)

- Первая строка — серая плашка «[Титульный лист — оформить самостоятельно]».
- Times New Roman 14, интервал 1.5, A4, поля: левое 3 см, правое 1.5 см, верх и низ 2 см; абзацный отступ 1.25 см.
- Структура:
  1. заголовок лабы;
  2. «Цель работы»;
  3. абзац «Работа выполнена в программе Blender 5.2, так как 3ds Max недоступен для установки. Для каждого инструмента … использован аналог (таблица 1)»;
  4. «Краткие теоретические сведения» — простым языком, как это устроено в Blender;
  5. «Таблица 1 — Соответствие инструментов 3ds Max и Blender»;
  6. задания — нумерованные шаги: что сделано, числа из методички, почему в Blender именно так;
  7. рисунки «Рис. N — …» с подписью под картинкой;
  8. «Ответы на контрольные вопросы»: у каждого вопроса два ответа — **3ds Max:** и **Blender:**;
  9. «Вывод».
- Каждое крупное задание начинается с новой страницы через `pageBreakBefore` у заголовка (отдельный PageBreak даёт пустые страницы).
- **Номера рисунков в тексте должны совпадать с реальной нумерацией** — перепроверь.

## Уроки лаб 5–7 (проверено в bpy 5.0)

- **Названия из `tools/ru.po` могут отличаться от «ожидаемых»:** Glare = «Блики» (а «Свечение» — это тип Bloom), Environment Texture = «Текстура окр. среды», Facing = «Направление», режим вьюпорта Rendered = «Рендер», Copy All to Selected = «Копировать всё на выделение», Duplicate Linked = «Дублировать с созданием связей». Всегда проверяй через polib.
- **Композитор 5.0:** `scene.compositing_node_group` = новая группа `CompositorNodeTree`; узла «Композит» нет — выход через `NodeGroupOutput` (сокет создать в `ng.interface`). У «Бликов» тип — сокет-меню `inputs["Type"]` ("Fog Glow", "Ghosts", "Bloom", "Streaks"…), «Размер» 0…1.
- **Видео:** `image_settings.media_type = 'VIDEO'`, FFMPEG, AVI + MPEG4; для MPEG4 ставь `constant_rate_factor='NONE'` и `video_bitrate≈6000`, иначе квадраты. Рендер 101 кадра 960×540 Cycles ≈ 9 мин.
- **«Выровнять объекты»** выравнивает только одноимённые стороны (низ-низ, центр-центр, верх-верх); «поставить на» = «Положительные стороны» + подъём.
- **Массив:** «Постоянное смещение» считается в масштабе объекта (если у объекта масштаб ≠ 1 — бери «Относительное»); «Смещение по объекту» с масштабом уменьшает и шаг.
- **Spacing Tool** = геометрические ноды «Кривую в точки» (COUNT) → «Экземпляр на точки» + «Информация об объекте»; образец с `hide_render=True` всё равно размножается.
- **Драйверы:** простые выражения (`-var + radians(7.5)`) проходят `is_simple_expression`. Цепочка драйвер → драйвер работает.
- **Чёрные пятна на рендере** почти всегда — совпадающие грани (две плоскости на одной высоте) или индекс материала, назначенный по порядку граней вместо принадлежности вершин.
- **Превью звёзд/мелких точек** уменьшай max-пулингом, иначе точки исчезают.
- **Одинаковые имена коллекций в разных сценах** получают «.001» — давай уникальные (с номером сцены).
- Трансформ-операторы (shrink/fatten, «Индивидуальные ориджины») в фоне без окна не срабатывают — строй bmesh-ом и честно пиши, что ручные шаги в окне не прогонялись.

- **Лаба 8 (проверено в bpy 5.0):** имена модификаторов и ограничителей обрезаются на 63 байтах (кириллица = 2 байта) — держи их короткими, имена объектов могут быть длиннее. Рендер кадра анимации: перед `frame_set` ставь `bpy.context.window.scene = sc`, иначе рендерится старый кадр. `matrix_world` сразу после открытия файла — единичная, бери `matrix_basis`. «Логический» на кривую не добавить — стены делай мешем: контур рёбер + «Винт» с углом 0 (высота) + «Объёмность». «Винт» по умолчанию включает гладкое затенение (`use_smooth_shade`). NURBS-поверхность: `p.co = (...)` целиком (через `p.co.z` не пишется), «Конечная точка» U/V — чтобы доходила до краёв. `Curve to Points` → Rotation кладёт экземпляры набок (ось Z по касательной) — для столбов не подключай.

## Сдача результата (для каждой лабы)

1. Всё положи в `output/`.
2. Проверь: открой .blend заново через bpy и выведи ключевые параметры; отчёт отрендери в картинки или хотя бы открой.
3. Commit + push в рабочую ветку.
4. В `output/ИТОГ.md` и в финальном сообщении:
   - что сделано и где файлы;
   - «Что пришлось сделать иначе, чем в методичке»;
   - что пользователю сделать самому: скриншоты по жёлтым рамкам и, если нужно, текстура в Photoshop.
