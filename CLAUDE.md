# Лабораторные по 3D-моделированию: методички под 3ds Max → выполнение в Blender

## Кто пользователь и что ему нужно

- Студент, курс «Мультимедиа технологии». Методички написаны под 3ds Max, но 3ds Max ему недоступен, поэтому всё делается в **Blender 5.2.1 с русским интерфейсом** на Windows.
- Для сдачи ему нужны:
  1. **Отчёт** — понятный текст по шагам и рисунки с подписями «Рис. N — …». Оформление (титульник, шрифты, поля) он делает сам.
  2. **Файл .blend**, который он откроет на защите и покажет, где какая настройка («потыкать»).
  3. **Понимание** — для этого пишется шпаргалка к защите.
- Его просьба: **если что-то не переносится из 3ds Max или пришлось сделать иначе — обязательно помечать.**
- Отвечать и писать всё по-русски, просто и коротко.

## Задача этой сессии

Сделать **лабы 5 и 6** (`metodichki/5.pdf`, `metodichki/6.pdf`) в том же формате, что лабы 3 и 4 (`examples/`). Для каждой лабы в `output/labN/`:

1. `ЛабаN_Blender.blend`
2. `Отчет_ЛабаN.docx`
3. `Шпаргалка_защита_ЛабаN.md`
4. Лаба 5 — ещё видео анимации `.avi`. Лаба 6 — использованные текстуры (.png), они же упакованы внутрь .blend.

В конце — `output/ИТОГ.md`: что сделано, где лежит, **список отклонений от методички и проблем**, что пользователю сделать самому (скриншоты по жёлтым рамкам). Затем commit и push в рабочую ветку. Финальное сообщение — то же самое, коротко.

Делай лабы по очереди: сначала 5 целиком (файл → рисунки → отчёт → шпаргалка → проверка → commit/push), потом 6. Так готовая лаба не пропадёт, если что-то сломается во второй.

## Окружение

- Blender как Python-модуль: `pip install bpy==5.0.1` — **нужен Python 3.11** (колёса только cp311). Если его нет:
  `pip install uv && uv python install 3.11 && uv venv -p 3.11 .venv && uv pip install -p .venv bpy==5.0.1 pillow numpy polib python-docx`
- Файлы, сохранённые из bpy 5.0.1, открываются в Blender 5.2.1 у пользователя.
- Рендерить можно только **Cycles на CPU** (EEVEE без GPU не работает). При этом в самом .blend оставляй движок **EEVEE**: у пользователя он быстрый.
- Отчёт: npm-пакет `docx` (v9, `npm install docx`). Генератор пиши по образцу `examples/lab4/make_report4.js`. **После генерации обязательно** `python tools/fixdocx.py Отчет.docx`: docx-js пишет границы абзаца (`w:pBdr`) в неверном порядке, Word на это ругается.
- Проверка отчёта: если есть LibreOffice — `soffice --headless --convert-to pdf`, затем `pdftoppm` и просмотр страниц картинками. Если нет — хотя бы открыть файл через python-docx.
- В скриптах из `examples/` зашиты пути старого окружения (`/tmp/claude-0/...`) — замени на пути этого репозитория.
- `tools/lab4_common.py` — полезные функции: материалы, кривые, камера, свет, мир (hex-цвета переводятся в линейные).

## Русские названия интерфейса

- `tools/ru.po` — официальный русский перевод Blender (5.3 alpha, совпадает с 5.2). **Все названия пунктов меню и параметров в отчёте и шпаргалке бери оттуда** (через `polib`), а не придумывай.
  Примеры: Color Ramp = «Градиентная карта», Bump = «Карта неровностей», Extrude у кривой = «Экструдировать», Selectable = «Доступно для выделения», Copy as New Driver = «Копировать как новый драйвер», Scripted Expression = «Скриптовое выражение».
- Учитывай `msgctxt`: у одного слова бывают разные переводы в разных местах.
- Если перевода нет — пиши английское название: так и будет в интерфейсе (например, у дополнений: Round Cube, Curve Profiles).

## Правила качества (выработаны на лабах 3–4)

1. Сначала прочитай методичку целиком (PDF по страницам) и составь таблицу «3ds Max → Blender».
2. **Любое поведение Blender, в котором есть сомнения, проверяй скриптом в bpy**, а не по памяти. Например, в лабе 3 так выяснилось, что ось изгиба «Простой деформации» — это ось, *вокруг* которой гнётся объект.
3. **Масштаб.** Числа из методичек (радиусы 40–70) в Blender становятся метрами. Последствия:
   - стандартные камера и лампа оказываются внутри объекта → ставь свою камеру и свет;
   - у камеры `clip_end` по умолчанию 100 → ставь 1000 и больше;
   - у узла «Карта неровностей» «Расстояние» по умолчанию 0.001 → ставь около 1, иначе рельефа не видно.
4. **В .blend:**
   - модификаторы НЕ применять — пользователь показывает их настройки на защите;
   - понятные русские имена объектов, модификаторов и материалов;
   - коллекции по заданиям; если заданию нужен свой свет и фон — отдельная сцена (как в лабе 4) с названием «1 — …», «2 — …»;
   - скрытая коллекция «Этапы … (скрыто)» (`hide_viewport` у layer collection + `hide_render`) с копиями модели на промежуточных шагах — по ним пользователь снимает скриншоты этапов;
   - камера и свет настроены так, что F12 сразу даёт хороший кадр;
   - картинки упаковывать внутрь файла (`image.pack()`).
5. **Драйверы — только «простые выражения»** (`driver.is_simple_expression == True`), иначе у пользователя без Auto Run Python они не сработают.
6. **Рисунки для отчёта:**
   - рендер Cycles, 40 сэмплов, денойз;
   - этапы — серый материал, чёрный каркас (копия объекта с модификатором Wireframe) и «студийный» свет со стороны камеры (см. `examples/lab4/render_lab4.py`);
   - для видов сверху и спереди — ортографическая камера;
   - **все рендеры просмотри** (собери контакт-лист) и поправь кадрирование и свет, прежде чем собирать отчёт.
7. **Скриншоты интерфейса сделать нельзя.** Вместо них в отчёте — жёлтая рамка «ВСТАВИТЬ СКРИНШОТ. …» с точной инструкцией: какую сцену и объект выбрать, какую вкладку открыть, что снять. Если для скрина нужно выполнить действие — допиши «потом Ctrl+Z».
8. Не утверждать в отчёте того, чего не было. Например, если текстура собрана скриптом, не писать «выполнено в Photoshop».

## Формат отчёта (образец — `examples/lab4/Отчет_Лаба4.docx`)

- Первая строка — серая плашка «[Титульный лист — оформить самостоятельно]».
- Times New Roman 14, интервал 1.5, A4, поля: левое 3 см, правое 1.5 см, верх и низ 2 см; абзацный отступ 1.25 см.
- Структура:
  1. заголовок лабы;
  2. «Цель работы»;
  3. абзац «Работа выполнена в программе Blender 5.2, так как 3ds Max недоступен для установки. Для каждого инструмента … использован аналог (таблица 1)»;
  4. «Краткие теоретические сведения» — простым языком, как это устроено в Blender;
  5. «Таблица 1 — Соответствие инструментов 3ds Max и Blender»;
  6. задания — нумерованные шаги: что сделано, числа из методички, почему в Blender именно так;
  7. рисунки «Рис. N — …» с подписью под картинкой;
  8. «Ответы на контрольные вопросы»: у каждого вопроса два ответа — **3ds Max:** и **Blender:**;
  9. «Вывод».
- Каждое крупное задание начинается с новой страницы через `pageBreakBefore` у заголовка (отдельный PageBreak даёт пустые страницы).
- **Номера рисунков в тексте должны совпадать с реальной нумерацией** — перепроверь.

## План по лабе 5 (анимация со связанными параметрами)

Уже продуман в прошлой сессии — проверь в bpy и выполни.

- **Шестерёнка** = кольцо (Tube: R1 = 60, R2 = 70, H = 9, Height Segments = 1) + внутренний диск (копия Tube с R2 = 9.1, H = 3 → диск от 9.1 до 60 с отверстием).
  - Tube в Blender нет. В файле строй через bmesh.
  - Для пользователя описать: «Окружность» с заполнением «Ничего» → E, S (60/70) → получилось кольцо → E по Z на 9.
  - Сторон 24 = 24 зуба, шаг 15°.
- **Аналоги:** Edged Faces = «Наложения» → «Каркас»; Clone → Copy = Shift+D; Align = «Объект → Трансформировать → Выровнять объекты» (или одинаковое положение в N-панели).
- **Зубья.** В 3ds Max: Ring (выделение кольца вертикальных рёбер) + Extrude рёбер с Base Width = 10. Прямого аналога выдавливания ребра в Blender нет. Решение: выделить кольцо наружных граней (Alt+щелчок в режиме граней), «Экструдировать отдельные грани» наружу примерно на 12, сжать вершины S ≈ 0.15 с центром трансформации «Индивидуальные ориджины» → острые зубья, как на рис. 3. **Пометить как отклонение.**
  Аналог кнопки Ring для рёбер: Ctrl+Alt+щелчок или «Выделить → Выделить петли → Кольца рёбер».
- **Вторая шестерёнка:** копия на расстоянии ≈ 150 по X (радиус основания + радиус вершины зуба), повёрнута на половину шага = 7.5° (это и есть «угол из п. 10»). Проверь зацепление рендером в нескольких кадрах.
- **Wire Parameters = драйверы** на «Вращение Z».
  - Для пользователя: ПКМ по полю «Вращение Z» ведущего кольца → «Копировать как новый драйвер» → ПКМ по полю другого объекта → «Вставить драйвер». Выражение правится через ПКМ → «Редактировать драйвер»: тип «Скриптовое выражение», переменная «Одно свойство» `rotation_euler[2]`.
  - В файле: Диск 1 = `var` (от Кольца 1); Кольцо 2 = `-var + radians(7.5)` (минус = вращение в обратную сторону); Диск 2 = `var` (от Кольца 2).
  - Двусторонней связи (`<-->`) у драйверов нет: только ведущий → ведомые, ведомое поле блокируется. **Написать это в отчёте.**
- **Анимация** ключами только у Кольца 1: кадры 0, 24, 41, 71, 100 с разворотом направления (например 0°, 120°, 60°, 240°, 180°). Диапазон кадров 0–100. AutoKey = «Автосоздание ключей» (кнопка записи на временной шкале); вручную — клавиша I. Play = пробел.
- **Материалы:** бронза, серебро, дерево (дерево процедурное: «Текстура волны» + «Градиентная карта»). Сказать пользователю, что материалы меняются под индивидуальное задание преподавателя.
- **Видео** (аналог F10 → .avi): Вывод → «Видео FFmpeg», контейнер AVI, кодек MPEG4 (играется в Windows), Ctrl+F12 — «Рендеринг анимации». Путь вывода в файле — относительный (`//...`).
  Сам отрендери видео в Cycles в небольшом разрешении (например 960×540, 16–24 сэмпла) и положи в output.
- **Рисунки:**
  - рендеры: кольцо + диск; кольцо с зубьями (вид сверху, каркас); две шестерёнки в зацеплении; 3–4 кадра анимации (0, 24, 41, 71);
  - заглушки: «Редактировать драйвер» с выражением, редактор драйверов, временная шкала с ключами, настройки вывода видео.
- **Контрольные (6):**
  1. классический метод — по ключевым кадрам;
  2. чем ключи отличаются от связанных параметров;
  3. зачем нужны связанные параметры;
  4. кнопка Ring (Blender: Ctrl+Alt+щелчок, «Кольца рёбер»);
  5. как заставить вращаться в разные стороны — минус в выражении (`-var`);
  6. что такое ключевые кадры и зачем они нужны.

## План по лабе 6 (космический пейзаж)

- **Задание 1 (текстура в Photoshop).** Photoshop у пользователя может не быть. Сгенерируй текстуру скриптом (numpy + PIL), повторяя шаги методички:
  1. 2500×2500, заливка чёрным;
  2. шум по Гауссу 10 %, монохромный;
  3. «Уровни» — поднять чёрную точку, чтобы остались только звёзды;
  4. новый слой с цветными пятнами → размытие по Гауссу > 30 → «Скручивание» (Twirl);
  5. прозрачность слоя 50–60 %, режим наложения «Экран».
  Промежуточные картинки — рисунки отчёта. В отчёте опиши шаги как шаги графического редактора (Photoshop или бесплатный Photopea), но в ИТОГ.md честно скажи, что картинка собрана скриптом по этим шагам. Если преподаватель захочет скриншоты Photoshop — шаги для повтора за 10 минут положи в шпаргалку.
- **Звёздное небо как окружение:** «Мир» → «Фон» ← «Текстура окружения», проекция «Равнопромежуточная» (аналог Spherical Environment). Для неё нужно изображение 2:1 — сделай вариант 5000×2500 или подобный и **пометь отличие от методички**.
  Видно в окне в режиме отображения «Рендеринг» или в «Предпросмотре материала» с включённым «Мир сцены» (аналог Viewport Background).
- **Планета:** UV-сфера радиусом 60. Этап с малым числом сегментов показывает «ломаный контур»; итог — 60 сегментов и «Гладкое затенение».
- **Текстуры планеты «из папки с лабораторной» у нас НЕТ.** Сделай свою (процедурный шум → equirect-картинка 2:1 через numpy или запекание в Cycles). **Пометь в ИТОГ.md.** В шпаргалке напиши, как заменить картинку в узле «Изображение», если оригинал найдётся.
- **Материал планеты:** Principled BSDF. «Основной цвет» ← картинка планеты; та же картинка → «Карта неровностей» («Сила» около 0.5 ≈ Bump 50, «Расстояние» подобрать под радиус 60) → «Нормаль».
- **Self-Illumination + Mask + Falloff.** «Излучение» = красный ободок (узел «Вес слоя», выход Френель или «Обращённость» → «Градиентная карта» чёрный → красный), умноженный на **инвертированную** маску «свет/тень» (скалярное произведение нормали и направления на источник → «Инвертировать»). Проверь, что работает в обоих движках.
- **Свет:** «Точечный источник» с «Радиусом» (аналог mr Area Omni, мягкие тени). Сам источник на рендере не виден → добавь в его точку маленькую сферу с сильным «Излучением» (аналог «сделайте видимым источник света»).
- **Lens Effects → композитинг:** узел «Свечение» (Glare). Fog Glow / Bloom ≈ Glow, Ghosts ≈ Auto Secondary, Streaks (16 лучей) ≈ Star.
  - В Blender 5.0 у композитора **новый API**: `scene.compositing_node_group`. Проверь в bpy, как создаются узлы и какие у Glare входы: многие параметры стали сокетами.
  - Флажок Interactive ≈ композитор во вьюпорте («Шейдинг вьюпорта» → «Композитор»).
- **Шаг 18 (сравнение визуализаторов)** = EEVEE против Cycles. Cycles-рендер сделай сам, для EEVEE — заглушка (F12 на машине пользователя).
- **Контрольные (5):**
  1. как сделать материал видимым в окне проекции (3ds Max: Show Standard Map in Viewport; Blender: режим «Предпросмотр материала» или «Рендеринг», клавиша Z);
  2. определение источника света;
  3. какие источники света бывают (3ds Max: Omni, Target/Free Spot, Target/Free Direct, Skylight, mr Area Omni/Spot, фотометрические, системы дневного освещения; Blender: Точечный, Солнце, Прожектор, Источник-область + освещение от мира и излучающие материалы);
  4. эффект бликов объектива (3ds Max: Lens Effects; Blender: «Свечение» в композитинге);
  5. зачем нужны Bump-карты — рельеф без усложнения геометрии.
